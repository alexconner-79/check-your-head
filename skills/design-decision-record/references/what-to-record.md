# What's worth recording

## Record it when

- There was disagreement, or more than one option was seriously considered
- A stakeholder overrode a design recommendation
- It trades user experience against something else (deadline, cost, compliance, tech constraint)
- It sets a precedent other teams will follow (a pattern, a component behaviour, a content rule)
- It's expensive to reverse
- It's likely to be questioned later ("why didn't we just...?")
- It creates UX debt (also log the debt, and link the two)
- It changes or departs from the design system

## Usually skip

- Routine execution that follows an existing pattern
- Visual polish with no trade-off
- Decisions fully captured elsewhere (an approved spec that already explains the why)

## Status values

| Status | Meaning |
|---|---|
| Proposed | Recommended, awaiting agreement |
| Accepted | Agreed and in effect |
| Superseded | Replaced by a later record (link it) |
| Reversed | Undone without a replacement (say why) |

## Good evidence

Strongest first: usability test results, analytics, research findings, accessibility standards (WCAG criterion), regulatory requirement, design system rule, precedent in the product, competitor pattern, expert judgement. "Judgement call" is a legitimate answer; say it plainly rather than dressing it up.

## Revisit triggers

Make them observable: "if completion drops below 45%", "when the new ID provider goes live", "if legal changes the disclosure wording". Avoid "if needed".
